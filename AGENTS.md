# Business objective

AlexBuild is not a developer portfolio.

It is a commercial website whose primary objective is to generate qualified leads.

The visitor should quickly understand:

1. What AlexBuild sells
2. What it costs approximately
3. Why the quality is better than a cheap template website
4. What AlexBuild can build
5. How to request a quote

Every major design or development decision should support at least one of:

* credibility
* perceived quality
* comprehension
* conversion
* performance

Do not add features merely because they look technically impressive.

# Visual direction

The existing black / charcoal / gold identity should remain the foundation unless there is a strong reason to adjust it.

Preferred palette:

* black
* charcoal
* warm dark tones
* off-white / light neutral surfaces
* restrained gold accent

Gold should communicate precision and premium quality.

Avoid excessive gold that creates a cheap "luxury" aesthetic.

Use contrast, typography, whitespace, scale, composition and motion to create impact.

The website should not rely only on color to feel premium.

Motion is an important part of AlexBuild's identity.

Use animation where it improves:

* storytelling
* hierarchy
* perceived quality
* interaction feedback
* transitions between sections

Possible techniques:

* text reveals
* scroll-triggered transitions
* subtle parallax
* project transitions
* cursor interactions
* hover animations
* navigation transitions
* masking
* clipping
* staggered reveals
* subtle transformations

Avoid using simple fade-in animations as the primary visual effect everywhere.

Animations must remain tasteful.

---

# Performance

Performance is non-negotiable.

The website itself is proof of AlexBuild's technical quality.

Prefer:

**95 Lighthouse + excellent design**

over:

**spectacular design + 55 Lighthouse**

Be careful with:

* large JavaScript libraries
* animation libraries
* WebGL
* videos
* oversized images
* unnecessary fonts
* layout shifts
* excessive event listeners
* scroll handlers

Optimize:

* LCP
* CLS
* INP
* images
* fonts
* JavaScript
* lazy loading
* asset loading

Do not introduce a large dependency for an effect that can reasonably be implemented with CSS or existing project tools.

---

# Responsive design

Mobile is a first-class experience.

Never create an impressive desktop page and simply stack everything vertically on mobile.

For every major component, consider:

* desktop
* tablet
* mobile
* touch interactions
* reduced screen height
* reduced motion
* performance

Disable or simplify expensive effects on mobile when appropriate.

Respect `prefers-reduced-motion`.

# Development rules

Before making significant changes:

1. Inspect the relevant existing files.
2. Understand the current architecture.
3. Reuse existing utilities/components when they remain appropriate.
4. Avoid unnecessary dependencies.
5. Preserve working functionality unless intentionally replacing it.
6. Check responsive behavior.
7. Check accessibility.
8. Check performance implications.
9. Do not silently remove existing SEO functionality.
10. Keep the codebase maintainable.

Do not rewrite the entire stack simply because another framework is preferred.

Do not introduce React, Vue, GSAP, Three.js or another large dependency unless it provides a clear benefit that justifies its cost.

Follow the conventions already present in the repository whenever they are reasonable.

---

# Code quality

Prefer:

* simple architecture
* reusable components where useful
* meaningful names
* small focused functions
* CSS variables/design tokens
* predictable responsive rules
* minimal dependencies

Avoid:

* premature abstraction
* massive components
* duplicated styles
* magic numbers everywhere
* unnecessary JavaScript
* dead code
* commented-out experiments left in production

---

# Agent autonomy

You are encouraged to make strong design decisions.

Do not constantly ask the user to choose between minor alternatives.

When the objective is clear:

1. inspect
2. reason
3. choose the strongest solution
4. implement it
5. verify it

Ask for clarification only when a decision would materially affect business requirements, data integrity, security, pricing, or functionality.

---

# Final principle

AlexBuild should never look impressive **only to developers**.

It should look impressive to the person who may actually spend €1,000–3,000 on a website.

Every decision should balance:

**WOW + credibility + clarity + conversion + performance.**
